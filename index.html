Batteries included for Go, one module at a time.

ubgo is an ecosystem for building Go apps, in the spirit of the components Laravel ships for authentication, caching, logging and configuration. Every piece is its own Go module, so a service imports only what it uses, from sign-in to caching. The main libraries share one shape, a small core with adapters outside it and a shared test suite, so learning one teaches you the next.

How ubgo compares

ubgo is not one framework you adopt whole. It is a set of Go modules that follow the same rules.

✓ubgo is

  • Separate Go modules. 238 go.mod files across the 46 public libraries. You add the ones you use. See the map
  • Small cores, adapters outside them. 84 adapter modules live in contrib/ folders, so an integration's dependencies stay out of your build until you import it. For example errx, logger and health.
  • Backends you can swap, checked by one suite. cache (cachetest), cache-obj (objtest), cfgkit (cfgkittest), sqlb (sqlbtest): a backend counts only when its tests run the suite.
  • Fits the HTTP stack you already use. health, shutdown and buildinfo ship adapters for net/http, Gin, Chi, Echo and Fiber, and auth works with net/http, chi, Gin, Echo, Fiber and gqlgen.

✕ubgo is not

  • A web framework. There is no ubgo router or request lifecycle. You keep your own, and the libraries plug into it.
  • An ORM. sqlb builds typed SQL; entkit and entx extend the ent ORM instead of replacing it.
  • All or nothing. A library needs another one only when its go.mod says so, and the map draws every one of those links.

How several of them are built

True for the libraries named under each one, as their READMEs state. Not a promise for every repo.

Small cores

The core module has no third-party dependencies, so importing it adds nothing to your go.sum.

errxloggerhealthshutdownbuildinfosqlblockhttpreq

Adapters live outside the core

Integrations (frameworks, OpenTelemetry, drivers, secret stores) ship as separate modules, so you only download what you import.
